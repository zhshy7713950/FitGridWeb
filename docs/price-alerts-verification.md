## 美股 demo 夜间报告复核

[报告首页](https://evoxt.9900102.xyz/stock-push-demo/minute-reports) 显示 2026-10-27 美股观察已完成，生成 39 份报告、跳过 0 个窗口。公开首页只列出最近 20 份，本次统计仅覆盖这些报告，目标窗口为 16:40–20:00 UTC，不能代表全部 39 份。

| 标的 | Yahoo | 东方财富备用 |

| SPY | 1/20 完整；19 次 OHLC 校验失败 | 20/20 完整 |

[收盘报告](https://evoxt.9900102.xyz/stock-push-demo/minute-reports/20261027T200030Z-0932b49a.json) 的目标窗口为 19:50–20:00 UTC，AAPL、SPY 主备均为 10/10。报告中的 HTTP 200 不能替代 OHLC 和窗口完整性验收。

失败报告未保存当时的原始 Yahoo 响应。收盘后重新请求的两份响应均有 391 个点，严格 OHLC 校验通过；其中 20:00 UTC 的额外单点不属于常规分钟区间。因此不能据现有证据确定昨晚具体坏字段，也不能断言是浮点精度问题。

代码检查发现一个可复现的问题：原逻辑先校验整份响应的 OHLC，再筛选目标分钟，窗口外或尚未完成的坏点也会使目标窗口失败。正式版改为先按目标窗口和接收时间筛选，再严格校验窗口内数据。回归覆盖窗口外坏点、未完成尾点、目标内异常、空分钟、额外收盘点与身份校验。目标内坏数据仍失败并尝试备用，不舍入修补、不补造、不放宽 OHLC 关系。此次没有修改独立 demo。

## 代码审查后的修复

- 日线基数校验最后有效交易日期、来源与当前交易日；无法确认停牌或新鲜度时，均线不可用并尝试备用整套数据，固定价格规则不受牵连。
- 并发任务发生错误时停止分派新任务，并等待所有已启动任务结束后再释放锁。
- 午休或跨日遗失的正常交易分钟保留连续性降级标记；普通休市时间不算缺口，不跨交易分段补拉。
- 维护恢复、健康回滚和快照失败恢复后，恢复原先运行的定时器；原先手动停止的保持停止，恢复的规则仍暂停。
- Bark 接受要求 HTTP 200 且业务 code=200；国内代码示例包含 `.SH` 后缀。

以上均有针对性回归。迁移、RLS、队列事务和 v3/v4 恢复使用本地 PostgreSQL 17 验证；通知使用本地 HTTP 替身，不发送真实 Bark。

## 容量与真实数据边界

本机原生 Vitest 进程与 PostgreSQL、模拟行情测得：50 个产品、250 条规则，共 50 次共享行情请求，来源并发峰值 4；生成 2500 条事件、250 条合并通知，本轮约 1.2 秒、进程 RSS 334 MiB。这不代表 Docker 容器或 VPS 的内存峰值，也不包含真实网络延迟。

本机只读真实请求中，腾讯三个国内标的的分钟及前复权日线通过；Yahoo AAPL、SPY 最近美股收盘窗口及调整日线通过，属于历史覆盖。东方财富在本机有请求失败及日线不可用，不能标记正式版双源通过。demo 的 VPS 分钟备用通过，也不能替代正式版同来源分钟与复权日线组合验收。
