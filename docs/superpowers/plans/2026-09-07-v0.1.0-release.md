# FitGridWeb v0.1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the verified `main` branch as FitGridWeb `v0.1.0`, produce its immutable amd64 GHCR image and GitHub Release, attach a commit-pinned production upgrade script, and stop the reusable local test VM.

**Architecture:** Keep the existing `Server image` workflow and production installer as the only build and deployment implementations. Release orchestration uses Git/GitHub CLI around those established interfaces; the attached wrapper only downloads the installer from the immutable release commit and delegates to its existing `--upgrade` path.

**Tech Stack:** Git, GitHub CLI, GitHub Actions, GHCR OCI images, POSIX shell, Lima, pnpm, Vitest, TypeScript, ESLint, Next.js.

**Spec:** `docs/superpowers/specs/2026-09-07-v0.1.0-release-design.md`

## Global Constraints

- The first annotated release tag is exactly `v0.1.0`.
- Publish only `linux/amd64` to `ghcr.io/zhshy7713950/fitgridweb:sha-<40-character-release-commit>`.
- Do not commit `.pnpm-store/` and do not produce an offline Docker image archive.
- Do not delete the Lima VM, its PostgreSQL volume, its current deployed image, or its single previous release directory.
- Do not force-push, move a published tag, overwrite an existing Release, or bypass a failed verification gate.
- The upgrade wrapper must not read or print secrets, change production topology, create an administrator, or duplicate installer logic.

- [ ] **Step 3: Create the minimal upgrade wrapper**

Read the final commit and installer checksum first:

```bash
release_sha=$(git rev-parse HEAD)
installer_sha256=$(git show HEAD:ops/install-production.sh | shasum -a 256 | awk '{print $1}')
test "${#release_sha}" -eq 40
test "${#installer_sha256}" -eq 64
```

Then use `apply_patch` to create `/tmp/fitgridweb-v0.1.0-upgrade.sh`. The two assignments must contain the literal outputs just obtained; the remainder of the file is exactly:

```sh
#!/bin/sh
set -eu

release_sha='${literal release_sha from the preceding command}'
installer_sha256='${literal installer_sha256 from the preceding command}'
temporary_directory=$(mktemp -d)
trap 'rm -rf "$temporary_directory"' EXIT HUP INT TERM
installer="$temporary_directory/install-production.sh"

curl -fsSLo "$installer" \
  "https://raw.githubusercontent.com/zhshy7713950/FitGridWeb/${release_sha}/ops/install-production.sh"
printf '%s  %s\n' "$installer_sha256" "$installer" | sha256sum --check --status

if [ "$(id -u)" -eq 0 ]; then
  exec sh "$installer" --upgrade --ref "$release_sha"
fi
exec sudo sh "$installer" --upgrade --ref "$release_sha"
```
