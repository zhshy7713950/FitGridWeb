# FitGridWeb 前端基础设计

日期：2026-09-01  
状态：已在对话中确认  
范围：登录页、会话入口、应用主框架、真实只读产品列表与既有一键部署链路

## 1. 目标

本阶段建立可持续扩展的前端基础，使用户可以完成“登录—恢复会话—查看并搜索自己的网格产品—退出”闭环。界面采用统一的 TradingView 风格金融工作台，后续新增、编辑、详情、导入导出和管理页面必须沿用本文定义的视觉令牌、布局边界与交互语言。

本阶段仍是 Next.js 模块化单体的一部分。前端页面和 `/api/v1` API 由同一个应用、同一个 Docker 镜像与现有一键安装脚本部署，不增加服务、容器或公网端口。

## 2. 用户与页面任务

面向偶尔使用 FitGridWeb 管理个人网格策略的受邀用户和管理员。产品强调纪律化计算、明确数据状态与长期可读性，不模拟实时行情或高频交易。

页面的单一任务：

- 登录页：安全进入个人策略工作区。
- 产品工作台：快速识别、搜索并浏览当前账号的网格产品。
- 应用外壳：提供稳定导航、会话身份、连接状态和后续功能扩展位置。

## 3. 范围

### 3.1 本阶段实现

- `/` 会话入口，根据 Better Auth 数据库会话进入登录页或产品工作台。
- `/login` 用户名与密码登录。
- `/grids` 受保护产品工作台。
- 登录后安全返回地址恢复。
- 会话失效统一回到登录页。
- 真实产品列表、名称/代码搜索、清除搜索、稳定游标分页与失败重试。
- 桌面表格和手机数据卡两种呈现，字段一致。
- 当前用户身份与退出。
- 加载、空列表、搜索无结果、网络错误、请求过快和服务错误状态。

生产 URL 由 Next.js `basePath=/fitgrid` 统一加前缀，因此对应为 `/fitgrid/login` 与 `/fitgrid/grids`。

### 3.2 本阶段不实现

- 公开注册、忘记密码或第三方登录。
- 新增、编辑、删除、详情和重新计算页面。
- 导入、导出和管理员页面。
- 实时行情、K 线、账户资产、收益统计或通知。
- 可切换主题；首期固定深色主题。

未实现功能不显示可点击的假入口。后续页面完成时再加入应用导航与操作区。

## 4. 路由与会话边界

### 4.1 路由

| 路由 | 类型 | 行为 |
|---|---|---|
| `/` | 服务端入口 | 有有效会话跳转 `/grids`，否则跳转 `/login` |
| `/login` | 公共页面 | 已登录用户直接跳转 `/grids`；匿名用户显示登录表单 |
| `/grids` | 受保护页面 | 服务端校验会话后渲染应用外壳和产品列表 |

所有重定向和链接通过统一的 base-path 辅助函数生成，不能硬编码部署根路径。

### 4.2 安全返回地址

登录页可接收不含 `basePath` 的应用内返回路由，例如 `/grids`。返回地址必须满足以下条件：

- 是以 `/` 开头的相对路径。
- 不能以 `//` 开头。
- 只允许 `/grids` 本身或其后续子路由；不能包含协议、主机或反斜杠。
- 导航前由共享路径函数应用当前 `basePath`，不能把用户输入直接交给 `window.location`。
- 无效值统一回退到 `/grids`。

本阶段实际受保护入口只有 `/grids`，但返回地址接口为后续详情深链保留安全扩展点。

### 4.3 会话

- 登录提交现有 `POST /api/v1/auth/login`。
- 浏览器依赖 Better Auth 的 `HttpOnly`、`Secure`、`SameSite=Lax` 数据库会话 Cookie。
- 前端 JavaScript 不读取或保存会话 token。
- 受保护页面在服务端读取会话，不能先渲染私有内容再由客户端跳转。
- 退出提交现有 `POST /api/v1/auth/logout`，成功后进入 `/login`。
- 任一产品 API 返回 401 时，前端进入登录页并附带经过验证的当前站内路径。

## 5. 信息架构与组件边界

### 5.1 页面结构

```text
RootLayout
├── LoginPage
│   ├── GridLadderBrandPanel
│   └── LoginForm
└── ProtectedAppLayout
    └── AppShell
        ├── DesktopRail / MobileNavigation
        ├── AccountBar
        └── GridsPage
            ├── GridListToolbar
            ├── DesktopGridTable
            ├── MobileGridCards
            └── GridListState
```

### 5.2 单元职责

- `RootLayout`：全局元数据、字体、主题色和基础样式。
- `LoginPage`：服务端会话分流和登录页面组合。
- `GridLadderBrandPanel`：只负责登录页的网格价格阶梯品牌表达。
- `LoginForm`：字段状态、请求提交和公开错误展示。
- `ProtectedAppLayout`：服务端会话门禁，将可信用户信息传给外壳。
- `AppShell`：桌面/手机导航结构、账户区和主内容插槽。
- `GridListToolbar`：搜索、清除、结果数量和刷新入口。
- `DesktopGridTable`：宽屏产品表格。
- `MobileGridCards`：小屏同字段产品卡片。
- `GridListState`：初始加载、加载更多、空态、无结果和错误状态。
- `apiClient`：base-path 感知的同源请求、错误信封解析和 401 统一处理。

组件不直接拼接 `/fitgrid`。URL 只能由共享路径函数生成。

## 6. 产品列表行为

列表连接现有 `GET /api/v1/grid-trades`：

- 默认每页 20 条。
- 搜索覆盖产品名称和产品代码。
- 输入变更经过 250ms 防抖后重新请求，查询变更时清空旧游标。
- 清除搜索立即恢复未筛选列表。
- 滚动距离列表底部 240px 内时请求 `nextCursor`；同一游标不能并发请求两次，同时保留可聚焦的“加载更多”按钮作为键盘和辅助技术入口。
- 新查询会取消旧请求；即使取消信号未及时生效，旧查询响应也不能覆盖当前查询。
- 刷新和分页失败保留已显示数据，并在对应位置提供“重试”。
- 首次失败显示页面级错误；错误文本附带服务端 `requestId`（存在时）。
- 无产品显示“还没有网格产品”；搜索无结果显示“没有匹配的产品”，两者不能混用。

字段与 Android App 一致：产品名称、产品代码、最高价、每份金额。产品名称为空时显示产品代码作为主标题。十进制保持服务端字符串，仅做安全的显示格式化，不用 JavaScript 浮点数重新计算。

本阶段列表行和卡片不链接未实现的详情页。

## 7. 登录与错误体验

### 7.1 登录表单

- 字段：用户名、密码。
- 浏览器自动完成属性使用 `username` 与 `current-password`。
- 提交时禁用重复提交并显示明确进行状态。
- 登录成功后替换历史记录进入安全返回地址，避免返回键再次提交登录。
- 页面可以保留用户名输入；密码不进入本地存储、URL、日志或错误信息。

### 7.2 错误映射

| 场景 | 页面行为 |
|---|---|
| 401 | 登录页统一显示“用户名或密码错误”；产品请求进入登录页 |
| 422 | 字段旁显示服务端字段错误并保留安全输入 |
| 429 | 显示服务端消息和 `Retry-After` 剩余时间，倒计时结束后可重试 |
| 网络中断 | 保留当前列表或表单，显示“网络连接失败，重试” |
| 500/503 | 显示“服务暂时不可用”和 `requestId`，不显示堆栈 |

界面文案使用主动、具体的中文；按钮与结果使用相同动作名称，例如“退出登录”成功后回到登录页，不显示含糊的“提交成功”。

## 8. 视觉系统

### 8.1 设计方向

采用受 TradingView 工具感启发、但属于 FitGridWeb 自身业务的“现代策略工作台”。视觉重点不是行情图表，而是网格计算中的离散价格阶梯、精确数字与清晰状态。

### 8.2 色彩令牌

| 令牌 | 色值 | 用途 |
|---|---|---|
| `canvas` | `#0B0F14` | 页面最底层背景 |
| `surface` | `#131722` | 主工作区与登录容器 |
| `surface-raised` | `#1E222D` | 菜单、浮层、强调区域 |
| `line` | `#2A2E39` | 边框与数据分隔 |
| `action` | `#2962FF` | 主操作、焦点与当前导航 |
| `positive` | `#089981` | 成功、连接和正向数值 |
| `negative` | `#F23645` | 错误、风险和破坏性操作 |
| `text` | `#D1D4DC` | 主文字 |
| `text-muted` | `#787B86` | 标签与辅助信息 |

颜色不能作为状态的唯一表达；状态同时包含文本或图标。

### 8.3 字体与数字

- 中文与普通界面：系统无衬线字体栈，优先 `PingFang SC`、`Microsoft YaHei`。
- 拉丁标题：`Inter` 风格的紧凑无衬线字体栈；不依赖运行时远程字体。
- 价格、金额、代码与时间：系统等宽字体栈，启用 `font-variant-numeric: tabular-nums`。
- 页面标题克制使用较大字号，不采用营销落地页式巨型标题。

### 8.4 标志元素与动效

登录品牌区使用“网格价格阶梯”：由等距水平价格档位、垂直跳阶和节点构成，直接来源于网格算法的业务语义。

- 只在首次进入登录页时完成一次 500–700ms 的阶梯绘制和表单淡入。
- 工作台不使用持续环境动画。
- `prefers-reduced-motion: reduce` 下禁用绘制、位移和平滑滚动。

### 8.5 响应式布局

桌面（`>= 1024px`）：

- 固定窄工具栏、顶部账户栏和宽内容区。
- 产品使用紧凑数据表，数字右对齐。

平板（`768px–1023px`）：

- 工具栏收窄为图标，内容仍优先表格。

手机（`< 768px`）：

- 顶部标题栏和底部导航替代侧边工具栏。
- 产品改为纵向数据卡，但仍展示名称、代码、最高价和每份金额。
- 搜索框固定在内容顶部；触控目标至少 44px。

## 9. 可访问性

- 页面使用真实 `main`、`nav`、`form`、`table`、标题和按钮语义。
- 所有交互可通过键盘完成，焦点环使用操作蓝与外层对比描边。
- 表格有标题单元格和可读 caption；加载状态使用非打断式 live region。
- 错误摘要与字段通过 `aria-describedby` 关联。
- 文字与背景满足 WCAG AA 对比要求。
- 登录品牌图形为装饰，不进入屏幕阅读器重复朗读。

## 10. 测试策略

实施遵循测试驱动开发。新增前端测试环境使用 Vitest、jsdom、React Testing Library 与 user-event。

关键行为测试：

1. 匿名访问根路径进入登录页，已登录进入产品页。
2. 登录提交真实 API 请求格式，成功进入安全返回地址。
3. 错误凭据使用统一信息，不泄露账号状态。
4. 429 展示等待时间，网络错误保留用户名且允许重试。
5. 受保护布局拒绝缺失或失效会话。
6. 列表呈现 API 的四个规定字段。
7. 搜索与清除重置游标，过期响应不能覆盖新查询。
8. 分页失败保留已加载项目并只重试失败游标。
9. 空账号与搜索无结果使用不同空态。
10. 401 进入登录页并生成安全返回地址。
11. 退出调用 API 并回到登录页。
12. 桌面表格和手机卡片保留相同可访问数据语义。

测试断言用户可见行为，不断言 CSS 源文本或模拟组件存在。

## 11. 生产构建与一键部署

前端和服务端继续共享当前生产路径：

```text
GitHub Actions
  -> NEXT_BASE_PATH=/fitgrid pnpm build
  -> 单个 Next.js standalone Docker 镜像
  -> GHCR 完整 commit SHA 标签
  -> /opt/fitgridweb/ops/install-production.sh --upgrade
  -> 现有 nginx /fitgrid 反向代理
```

- Dockerfile 不增加运行进程；静态资源由 Next.js standalone 应用提供。
- Compose 不增加服务、端口或内存限额。
- 安装器继续解析公开 Git ref、匿名验证镜像、迁移、更新应用、生成 FitGrid 托管 nginx 片段并执行健康检查。
- `sing-box`、订阅端口 `30127`、订阅路径 `/s` 和对应 nginx vhost 不在前端变更范围内。
- CI 必须继续执行测试、类型检查、Lint 和 `NEXT_BASE_PATH=/fitgrid` 生产构建后才发布镜像。

## 12. 验收标准

- 用户可在桌面和手机完成登录、会话恢复、查看/搜索/分页自己的产品及退出。
- 未登录或失效会话不能短暂看到私有工作台内容。
- 登录、列表和退出均使用现有 API 与标准 Better Auth 数据库会话。
- 视觉符合本文 TradingView 风格令牌和网格价格阶梯标志元素。
- 所有新增交互具备键盘、焦点、加载、空态和错误状态。
- `/fitgrid` 本地生产构建通过。
- 现有一键脚本无需增加前端部署步骤即可部署新镜像。
- 升级后 `/fitgrid/`、`/fitgrid/api/v1/health` 和原有 sing-box 订阅均保持正常。

## 13. 后续页面约束

新增/编辑、详情表格、行明细、导入导出和管理页面必须复用相同 AppShell、路径工具、API 错误模型、颜色和数字排版。允许在详情页增加网格类型语义色和高密度表格交互，但不得重新建立第二套主题或导航结构。
