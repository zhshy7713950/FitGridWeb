# FitGridWeb v0.1.0 Release Design

## Goal

Publish the current reviewed `main` branch as the first FitGridWeb release, `v0.1.0`, produce its immutable `linux/amd64` GHCR image, provide a commit-pinned production upgrade script, and stop the local test VM without deleting reusable test data.

## Release boundary

- The release tag is the annotated tag `v0.1.0`.
- The release commit is the final verified `main` commit after this design and its execution plan are committed.
- `.pnpm-store/` is a local dependency cache and must not be committed.
- Existing clean worktrees contain no unpublished changes; their commits are already ancestors of `main`.
- The published runtime artifact is `ghcr.io/zhshy7713950/fitgridweb:sha-<40-character-release-commit>` for `linux/amd64`.
- No offline Docker image archive is produced.

## Local test resource cleanup

Before stopping `fitgrid-amd64`, remove only the temporary source archive, temporary deployment script, and extracted build directory created for the local deployment. Stop the VM to release CPU and memory. Preserve the VM disk, PostgreSQL volume, currently deployed image, and one previous release directory so a future test or rollback does not require rebuilding the environment.

## Verification and publication flow

1. Confirm `main` contains all intended tracked changes and only `.pnpm-store/` remains untracked.
2. Review the release diff from `origin/main` and verify that nested `.worktrees/` and `.pnpm-store/` copies are excluded from local test discovery.
3. Run the complete non-browser Vitest suite, the production UI smoke workflow, TypeScript, ESLint over the real source tree, and a `/fitgrid` production build.
4. Push `main` without force and wait for the `Server image` workflow triggered by the push.
5. Create and push annotated tag `v0.1.0` at the verified release commit, then wait for the tag-triggered workflow.
6. Verify that the exact SHA image is anonymously readable from GHCR and inspect its platform metadata.
7. Create GitHub Release `v0.1.0` with generated notes and the production upgrade script attached.

If verification, push, either Action run, or GHCR verification fails, stop before creating the next irreversible publication object. Existing tags and releases must not be force-moved or overwritten.

## Production upgrade script

The release asset is named `fitgridweb-v0.1.0-upgrade.sh`. It embeds the final 40-character release commit SHA rather than relying on a mutable branch or tag during installation. It downloads `ops/install-production.sh` from that exact commit and invokes:

```sh
sudo sh "$installer" --upgrade --ref "$release_sha"
```

The existing production installer remains the single owner of environment reuse, public-image validation, source checkout, migration ordering, application health checks, nginx validation, systemd activation, and rollback. The wrapper must not read or print secrets, bypass interactive operational confirmation, alter ports or domains, create an administrator, or implement a second deployment path.

## Release contents and notes

The GitHub Release should identify this as the first version and summarize the complete grid workflow, account administration, backup and restore controls, responsive mobile grid actions, and the pinned production deployment model. It should link the GHCR SHA image and include the upgrade script asset. GitHub-generated notes may supply the detailed commit list.

## Acceptance criteria

- `fitgrid-amd64` is stopped and its reusable disk/data remain present.
- The local release worktree is clean apart from the pre-existing ignored-by-policy `.pnpm-store/` cache.
- Local release checks complete with zero failures.
- `origin/main` contains the final release commit.
- Annotated tag `v0.1.0` points to that exact commit locally and on GitHub.
- Both required GitHub Actions runs complete successfully.
- The exact SHA image is anonymously readable and reports `linux/amd64`.
- GitHub Release `v0.1.0` is published with the upgrade script asset.
- The final handoff includes the release URL, image reference, upgrade script URL, checksum, and production command.
