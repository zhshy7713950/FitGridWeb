# FitGridWeb 剩余前端与 Android JSON 导入设计

## 1. 背景与目标

FitGridWeb 已完成 Better Auth 数据库会话、服务端网格领域能力、账号隔离、导入导出接口、登录页、应用主框架和产品列表。下一阶段需要补齐首期剩余前端页面，使普通用户能够在手机和 PC 上完成完整的网格产品工作流，并使管理员能够管理邀请和账号状态。

本阶段同时验证并交付 Android JSON 手动迁移链路：用户从 Android 应用导出 JSON，在 Web 页面上传预检并导入到当前登录账号。该能力是用户主动触发的文件导入，不是 Android 与 Web 的实时或双向自动同步。

## 2. 已确认约束

- 延续已确认的 TradingView 风格：深色、高信息密度、专业金融工具感。
- 手机与 PC 使用相同业务路由、API、权限和服务端计算结果。
- 手机不使用底部导航；统一通过顶部栏和菜单进入功能。
- 普通页面不展示算法版本。
- 网格算法只在服务端执行，浏览器不复制权威算法。
- 所有产品数据仍由当前 Better Auth 会话确定 owner；客户端不能指定 ownerId。
- 管理员只能管理邀请和账号状态，不能读取其他用户的产品。
- 前端继续编译进现有 Next.js 应用，通过现有一键部署脚本、systemd 和 nginx `/fitgrid` 子路径一并部署。

## 3. 交付顺序

采用业务闭环优先的顺序：

1. 产品新增、编辑、删除。
2. 产品详情、网格表格、行明细和重新计算。
3. Android JSON 与 Web 备份导入。
4. Android JSON 导出与 Web 完整备份。
5. 接受邀请和修改密码。
6. 管理员邀请与用户启用、禁用。

每一阶段先完成组件和请求层自动化测试，再接入页面；最后统一进行响应式浏览器验收和生产构建验收。

## 4. 页面与导航

### 4.1 路由

| 路由 | 用途 | 访问权限 |
|---|---|---|
| `/grids` | 产品列表、搜索、刷新和分页 | 已登录用户 |
| `/grids/new` | 新增产品 | 已登录用户 |
| `/grids/[id]` | 产品详情、汇总、网格表格和操作 | 当前产品 owner |
| `/grids/[id]/edit` | 编辑产品 | 当前产品 owner |
| `/grids/import` | 文件选择、预检、冲突策略、提交和报告 | 已登录用户 |
| `/settings/security` | 修改密码 | 已登录用户 |
| `/admin` | 创建邀请、用户列表和账号状态 | 管理员 |
| `/invite/[token]` | 查看邀请状态并注册 | 匿名可访问 |

导出是数据管理操作，不单独设置页面路由；入口与导入并列，并通过用途说明对话框选择下载格式。

### 4.2 响应式导航

- PC 保留固定左侧导航和顶部账号区，工作区充分利用宽度。
- 手机使用顶部栏和菜单，不固定底部导航，避免内容和系统浏览器控件重叠。
- 管理员入口只在当前会话角色为管理员时显示；服务端仍执行最终授权。
- 深链页面在未登录时进入登录流程，并保留经过校验的站内返回地址。

## 5. 产品新增与编辑

表单分为“基础信息”“交易参数”“高级参数”三组，字段、默认值和校验规则沿用 `docs/fit-replication/02-functional-spec.md`。

- 方向使用尺寸足够、状态清晰的做多/做空分段按钮。
- 做空时隐藏并清空 `keepShare`、`mediumAmplitude` 和 `bigAmplitude`，隐藏值不能参与提交或计算。
- 前端提供即时格式提示，但不替代服务端权威校验。
- 422 字段错误显示在对应控件附近；409 产品代码冲突聚焦产品代码输入。
- 提交期间禁用重复保存。
- 新增成功进入新产品详情；编辑成功进入更新后的详情。
- 表单存在未保存修改时，取消、返回或关闭页面需要确认。

## 6. 产品详情与网格行

详情页顶部显示产品名称（为空时显示产品代码）、产品代码、方向和核心汇总。主要操作为重新计算、编辑和删除。

- PC 使用完整宽表显示现役功能规格中的全部网格字段。
- 手机允许横向滚动，并保持序号或关键价格列可辨认。
- 做空模式交换买入与卖出相关列的展示顺序。
- 小网、中网、大网使用文字和颜色双重语义标识。
- 点击非汇总行打开行明细；PC 使用右侧抽屉，手机使用接近 App 的全屏面板。
- 行明细支持上一笔和下一笔，首尾按钮禁用，切换时同步表格选中状态。
- 重新计算期间显示居中加载提示并阻止重复点击；成功后原位更新详情。
- 删除确认展示产品名称和代码，并要求用户明确确认不可撤销操作；成功后返回列表。

## 7. Android JSON 与 Web 备份导入

### 7.1 流程

1. 用户选择 `.json` 文件。
2. 浏览器检查文件类型和 10 MiB 上限。
3. 上传到 `/api/v1/grid-trades/import/preview`。
4. 页面分区展示新增、冲突、无效和警告。
5. 用户选择冲突策略并提交到 `/api/v1/grid-trades/import/commit`。
6. 页面展示新增、覆盖、跳过和无效数量，并提供返回产品列表入口。

### 7.2 冲突与失败

- 默认冲突策略是 `skip`。
- `overwrite` 使用风险色和二次确认，并提示先下载 Web 完整备份。
- 无效记录不写入；数据库阶段任一错误使整批事务回滚。
- 预检令牌 15 分钟后过期且只能使用一次；过期或已使用时要求重新选择文件。
- 提交期间禁止重复点击。
- 导入文件中的 owner、网格行和汇总值不可信；owner 来自会话，派生值由服务端重新计算。
- 导入成功后重新获取产品列表，服务器数据库成为 Web 端权威数据源。

### 7.3 真实 Android 文件验证

用户提供的 `grid_trade_data_1788327524504.json` 仅在本地用于兼容验证，不提交原始数据。验证结果：

- 文件大小 128205 字节，顶层为 30 条记录数组。
- 30 条记录全部通过当前严格解析和领域校验。
- 文件内没有重复产品代码。
- 30 条记录均带 Android 派生行和汇总；这些字段会被忽略并重算。
- 服务端对 30 条记录重新计算后，汇总和全部网格行均与 Android 文件逐字段一致。
- 样本全部为做多产品；做空导入仍由既有黄金 fixture 和自动化测试覆盖。

自动化测试使用脱敏后的最小结构样本，不复制或提交用户原始产品数据。

## 8. 导出

数据管理入口提供两个选择：

- Android 兼容 JSON：当前账号的 Android `GridTrade[]`，包含服务端重新计算后的派生结果，用于返回 Android 应用或兼容迁移。
- Web 完整备份：包含格式版本、时间、算法版本和稳定元数据，用于服务器迁移与恢复。

下载界面必须解释两种格式的用途。所有导出只包含当前账号的数据，不提供管理员跨用户导出。

## 9. 邀请、密码与管理

### 9.1 接受邀请

- 页面加载后显示有效、已使用、已过期或无效状态。
- 只有有效邀请显示用户名和密码表单。
- 密码规则与服务端一致；成功后进入登录页。
- 不显示邀请创建者或账号统计。

### 9.2 修改密码

- 设置页提供当前密码、新密码和确认密码。
- 成功后撤销其他会话并保留当前会话语义，以现有服务端接口为准。
- 密码字段不写入持久化浏览器存储。

### 9.3 管理员页面

- 创建邀请并提供一次性复制链接。
- 展示账号名称、角色、状态和创建时间，不展示产品数据。
- 启用或禁用账号前确认；禁用后服务端撤销目标账号会话。
- 当前用户不能通过前端制造使系统失去最后可用管理员的明显误操作；最终规则由服务端响应决定。

## 10. 前端状态与错误处理

- 列表只在首次进入、搜索、翻页、导入完成或手动刷新时请求，不进行轮询。
- 写操作使用明确的空闲、提交中、成功和失败状态，提交中禁用重复操作。
- 401 跳转登录；404 使用资源不存在页面；409 和 422 保留表单输入；429 显示稍后重试；网络错误保留当前页面和数据。
- 错误界面优先显示服务端公开消息和 requestId，不展示堆栈或敏感信息。
- 本地 UI 演示适配器与生产 API 适配器分离，生产构建不启用模拟行为。

## 11. 测试与验收

自动化与人工验收覆盖：

- 产品新增、编辑、删除、代码冲突和未保存离开确认。
- 做多/做空切换、隐藏字段清空和服务端字段错误映射。
- 详情、重新计算、网格行明细与手机横向表格。
- 导入预检、skip、overwrite、无效文件、过期令牌和重复提交。
- 两种导出的响应类型、文件名和下载触发。
- 邀请状态、注册、改密、管理员授权和账号启禁用。
- 未登录深链、跨账号 404 和普通用户管理页 403。
- PC 与手机关键流程及 `/fitgrid` 子路径运行。
- 完整单元/组件/API 测试、TypeScript、ESLint 和生产构建。

真实 PostgreSQL 的事务、RLS 和账号隔离继续作为生产发布门禁，在具备 `TEST_DATABASE_URL` 的环境执行。

## 12. 部署与运行影响

本阶段不增加容器、端口、数据库服务或后台轮询任务。所有前端页面继续由同一 Next.js 应用提供，现有 Docker Compose、systemd 自启动和 nginx 子路径配置保持不变。

代码合并并推送后，VPS 运行现有升级命令即可同时升级前后端。低内存部署继续使用既有 swap 和容器内存限制；新增前端页面主要增加构建产物，不引入常驻独立进程。

## 13. 非目标

- Android 与 Web 的实时、定时或双向自动同步。
- 浏览器离线编辑和待同步队列。
- 管理员读取或导出其他用户产品。
- 客户端计算成为权威结果。
- 将用户提供的原始 Android JSON 提交到仓库。
